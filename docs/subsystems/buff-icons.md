# Buff / debuff icon bar (lane buff-icons)

Median shows the player's active buffs and debuffs as a row of small icons above the bottom panel. D2Sigma draws them;
D2R HD does not. The port draws the same bar with the plugin's OverlayService (`plugin/src/buff_icons.cpp`, off word
`bufficons`). Data: `tools/state_icons.py`; layout, order, timer text: `plugin/src/buff_icons_logic.h` (unit tests
`plugin/tests/buff_icons_test.cpp`); game check `bufficons`.

## How D2Sigma draws it

All of it is in `ui/BottomPanel.cpp` (D2Sigma.dll image base 0x10000000). Evidence: the decompile in
`mxl_extracted/4_sigma_source/engine/ui/BottomPanel.cpp` (left group loop at line 2100, right group at line 2590, icon
windows `BottomPanel:StateIconCanvas-` line 941 and `BottomPanel:StateIcon-` line 1088; the loop walks `gpSigmaTables->nStateIcons`
rows of 8 bytes from table pointer +0x84, skips state -1, tests the side byte (0 left / 1 right), requires the frame to be
inside the loaded `game\skills\state-icons` sheet and asks `D2Units_100befc0(state)`).

| Function | What it does |
|---|---|
| `FUN_100cfd20` | builds the panel object; creates the two icon groups (token 1 = left, token 2 = right) with **10 icons per row** (field +0x1c) |
| `FUN_100d28e0` | per frame: the left group |
| `FUN_100d34b0` | per frame: the right group |
| `FUN_100d1230` | draws one icon: the frame of `state-icons.dc6`, tinted by the row's tint byte, and registers the hover rectangle |
| `FUN_100befc0` | "does the player have state n" (the `HasState` call on the client unit) |

* **Source table**: `stateicons` (236 rows of 8 bytes: `i16 state, u8 side, u8 tint, u16 frame, u16 tooltip`;
  `research/sigma_schema.json`, `docs/sigma-tables.md`, read by `tools/sigma_tables.py`). Rows with state -1 are skipped
  (`*psVar4 != -1`). A state without a row shows no icon.
* **Order**: for each group (left, then right) the table is walked in row order; every row of that side whose state the
  player has takes the next slot. Slot n is column `n % 10`, row `n / 10`; a full row of 10 starts a new row **upward**.
  There is no sorting by time or by skill; the table order is the order.
* **Place** (Median's 1024 x 768 screen): icon 28 x 28, pitch 32. Left group: x = 177 + 32 * column. Right group:
  x = 817 - 32 * column (first icon at the right end, growing left). Bottom edge of the first row y = 698, then 698 - 32 * row.
* **Groups**: left = the player's own buffs, auras and forms (176 of the 234 used rows); right = curses and debuffs (58 rows).
  The tint byte is 0-12 (0 = as drawn, 1 red curses, 3 blue, 4 gold buffs, 9 yellow, 11 purple, 12 green); the art is grey and
  the byte lines up with Diablo II's text colour indices.
* **Tooltip**: hovering an icon shows the string of the row's tooltip id (`medianxl:Skillname...` keys; 5382 = "dummy"
  = no tooltip, 141 of 234 rows have none).
* **Hidden**: when the UI mode global `DAT_101f1080 == 3`; mode 2 hides only the left group, mode 1 only the right group;
  also hidden while `DAT_1033d24c != 0` (cutscene / loading).
* **Timer text: none.** D2Sigma's bar has no text on the icons. The task named a separate `buff_timer_hook.cpp`
  (`mxl_extracted/buff_timer_hook.cpp`, also cited by `docs/sigma-tables.md` and `research/sigma_schema.json`); the file is not
  in the repo, in `mxl_extracted/` (searched by name) or under `research/`, and the decompiled `BottomPanel.cpp` has no text
  drawing or time formatting for the icons. The timer is therefore a port decision.

## D2R has nothing to reuse

* `hudpanelhd.json` (the HD HUD layout) has no widget for status icons, and the install's `filelist.txt` lists no buff-bar
  layout or sprite sheet; D2R shows no list of the player's active buffs. There is nothing to reuse.
* The PluginSDK services: OverlayService draws **lines, rectangles, filled rectangles and text** only (no sprites);
  WidgetService and PanelService can register panels but cannot place or switch a frame at run time (`widgets.h`,
  `panels.h`: layouts are static JSON).

## What the port does (drawing choice)

1. `tools/state_icons.py` reads `stateicons.bin`, maps each state row through `work/named/idmap.json` to the migrated D2R
   state id, resolves the tooltip string id to a full key (`medianxl:<key>` or `d2r:<key>` through
   `work/mod/strings_idkeys.json`; the same resolution as the NPC actions), and decodes the 193 distinct `state-icons.dc6`
   frames the table uses with the skill icons' DC6 reader and palette (`tools/skill_icons.py`).
   * `plugin/src/mxl_state_icons.h` (committed): 234 rows `{state, side, tint, frame, tooltip}`.
   * `plugin/src/mxl_state_icon_art.h` (committed, regenerated by the build, 542 KB): the frames as 28 x 28 palette indices + the palette.
     It is Median's art, so it is regenerated by `tools/build.py` and never committed (like every other extracted asset).
2. At plugin start each row's frame is turned into filled rectangles (the row's tint applied, same-colour runs merged
   greedily; `BuildRects`). Every overlay frame the bar reads the local player's states, places the icons exactly as
   D2Sigma does (`Place`, `SlotRect`) and draws the rectangles scaled by `screenHeight / 800` (nearest neighbour, edges snapped
   to whole pixels so there are no seams).
3. **Alternatives**: a native widget/panel cannot place an icon or switch its frame at run time (static JSON layouts), so it
   is out. The task's fallback, a hook into D2R's HD HUD draw to blit real sprites, was not needed because the SDK route
   works and a renderer hook is the riskier and less portable option; if the rectangle bar proves too costly or too coarse
   it is the next step (docs/unported.md).
4. **Placement in HD**: Median's pixel positions refer to the 1024 x 768 classic panel. The HD HUD is laid out in units that
   scale with the screen height (`buff_icons_logic.h`: health orb edge 812 units left of the centre, mana orb edge 814
   right of it, first row 232 units above the bottom; icon = 28 * height / 800 pixels, 37.8 px at 1080p). The left group starts
   at the health orb's inner edge and grows right; the right group starts at the mana orb's inner edge and grows left. The
   first guess (812 units from the centre, 232 above the bottom) put the icons over the orbs; measured on the 1600 x 900
   capture of the game check (`bufficons_bar.png`: the orb frames end 338 px from the centre, the belt's top edge is at y = 815)
   the constants are now **680 units from the centre and 176 units above the bottom**, i.e. the first icon at x = 460,
   bottom edge y = 812, 31 px wide. Calibrated for one resolution only (16:9); the unit scales with the height, so other
   16:9 sizes follow, an ultrawide screen is not checked.
5. **States**: read from the client's copy of the local player (`HasState` 0x3351b0 on the unit of the local slot
   `0x2a23704` / `0x9a480`), the same bits D2Sigma reads, so in a multiplayer game the icons need nothing from the server.
6. **Timer**: the end frame of a state lives in the server unit's state list (`0x2f5940`, float at list +0x24; game frame
   at `game+0x170`, 25 per second). `BuffIconsFrame` samples it every 5th game frame from `goblins.cpp` `FrameHook`
   (the same game-thread hook the other parts use); the overlay interpolates with `GetTickCount64` (at most 30 frames
   ahead, so a paused game stops). Single player and the host of a game see timers; a joining client has no server unit
   and shows the icons without timer. Format (`FormatRemaining`): `45s` under a minute, `5:07` under an hour,
   `1:02:03` above; no text for permanent states (no list, end frame 0, or more than 100 hours).
7. **Hover**: the cursor is read with `GetCursorPos` + `ScreenToClient` (read-only) when the window under it belongs to this
   process; the harness verb `bufficons hover` overrides it so the background-mode check can hover without the real mouse.
   The tooltip is a dark box with the row's string (first line gold), kept on the screen (`TooltipRect`).

## What was verified, and what was not

* **Verified by counters** (game check `bufficons`, plugin log): the icons of each state, the group, the slot order (table order,
  slots 0..n-1), the draw requests (0 refused, about 2700 rectangles per frame, 60 FPS held), the timers (597 s -> 592 s over
  5 s), the hover tooltip (state, one line), the icons going when the state is cleared; all five test states reached the
  client through D2R's own packets (the harness `setstate` on the server's player).
* **Not verified on screen.** The loader's overlay is **not part of a PrintWindow capture** of the background window (and
  `ImageGrab` of the window's rectangle did not show it either; the window may be covered): a magenta probe rectangle
  (`bufficons probe`) whose overlay calls all return Success is not in the picture, while D2R's own ImGui debug toolbar is. The
  dungeon lockout's timer (docs/unported.md) showed the same. So **nobody has seen the bar yet**: neither the art, the placement
  (calibrated from the HUD in the capture, not from the bar itself), the tint colours nor the tooltip box. They need a look in a
  normal (foreground) game window. The check's pixel comparison was therefore dropped; the screenshots (`bufficons_bar.png`,
  `bufficons_probe.png`, `bufficons_hover.png`) show the HUD for the human, not the bar.
* The cost of the rectangle route (about 490 rectangles per icon, merged same-colour runs) was measured only for 3-5 icons.
  If it shows in a heavy fight, the next step is a real sprite blit through a hook of D2R's HD HUD draw.

## Approximations (docs/unported.md)

* **Tint** (approx): the byte is applied as Diablo II's text colour multiplied with the icon's brightness. The engine call
  that consumes the byte in `FUN_100d1230` (component +0x1c) was not decoded; a PL2 palette-shift variation was tried and
  does not change grey art, so the text-colour reading is the best fit. Most rows (and all of the grey art in the
  checked frames) use tint 0 = as drawn.
* **Hidden states**: the bar is drawn whenever there is a local player. D2Sigma's UI-mode and cutscene conditions have no
  D2R counterpart read yet, so full-screen panels do not hide it.
* **Tooltip text**: rows without a tooltip string show only the timer.
