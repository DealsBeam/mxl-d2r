# Stash pages (audit GS5, lane stash-pages; GS7 not done)

Median's personal stash has ten pages (14 x 14 each) with Prev / Next / Mode / Sort buttons and an "n / 10" counter. D2R has one
personal page and an account-wide shared stash with tabs. This document is the design of what the port can do safely, what it
does, and what is left. Off word: `stashpages` (`mxl-core-off.txt`). Code: `plugin/src/stash_pages.cpp`, UI strip and panel
generated by `tools/ui_layouts.py` (`plugin/src/mxl_stash_page.h`).

## 1. Research: how D2R 3.3 stores and draws the stash

* **Personal stash** is item page 4 (STASH) of the character's `.d2s`, one grid, sized by `inventory.txt` Big Bank (14 x 14 in
  the port, like Median). It is drawn by the stock panel `BankExpansionLayout` (type BankPanel, PanelManager name).
* **Shared stash** is the account file `SharedStashSoftCoreV2.d2i`: tabs (D2R's 3 + `add_shared_tabs`). The port sets
  `add_shared_tabs = 7` (install_mod.py) so there are 10 shared pages. They belong to the account, not to the character.
* **D2RLoader 1.3.1 (PluginSDK ABI 4)** adds exactly ONE custom player page per game: `InventoryService::registerPlayerPage`
  with a logical id. D2RCore saves it as item page 6 of the `.d2s` (4-bit coordinates, so at most 16 x 16) and its own sidecar
  `<char>.d2rl`, and restores it on load. The page is "protected": a character that has items on it refuses to load when no
  plugin provides the page (so nothing is silently dropped). A page can be bound to a plugin panel grid
  (`bindPlayerPageGrid`) and ItemService can move items between the pages in one transaction.
* There is no API to add more than one custom page, to resize the stock stash, or to swap a page's contents in and out.
* Plugin panels (PanelService) take a strict JSON layout resource (`data/global/ui/layouts/mxl-core/<Name>hd.json`), may sit in
  `GameplayLeftSlot`, and close with Esc (`CloseOnEscape`). A custom UI message target never reaches a plugin listener; the
  stock `PanelManager` messages (`OpenPanel`, `ClosePanel`, `TogglePanel`) do work from a layout button.

## 2. Approach

**Two personal pages, not ten.** The stock stash is page 1 and the one custom player page is page 2, both 14 x 14, both drawn
with the same Median stash art. A "1 / 2" strip with two arrows sits under the stock stash and under the plugin panel.

Why not ten: the only place the game saves extra items safely is that one custom page. Faking pages 3-10 would mean parking item
pages in a sidecar the port writes itself (see section 7), which D2R does not know about; a crash between "swap out" and "swap
in" loses items. The task said to ship the safe part and state what remains; this is that.

## 3. Save layout

| Page | Where | Notes |
| --- | --- | --- |
| 1 (stock stash) | `.d2s` item page 4 | untouched, vanilla format |
| 2 (plugin page) | `.d2s` item page 6 + `<char>.d2rl` | written by D2RCore; vanilla tools stop at / ignore page 6; 14 x 14 (limit 16 x 16) |
| shared 1-10 | `SharedStashSoftCoreV2.d2i` | stock format, `add_shared_tabs = 7` |

The page is registered with logical id `stash2`. A character that has items on page 6 needs the plugin (and the page id) to
load; without it the load stops with two ERROR lines (see section 6) and the save file is not changed (hash checked).

## 4. UI

* The stock layout `bankexpansionlayouthd.json` gets a child `MxlPersonalNavigation` (text "1 / 2", two arrow buttons) from
  `tools/ui_layouts.py` `stash()`. The right arrow sends `PanelManager:TogglePanel:mxl-core/StashPage2`.
* The plugin panel `mxl-core/StashPage2` (GameplayLeftSlot, CloseOnEscape) is laid over the stock panel, which stays logically
  open underneath. Its left arrow sends `PanelManager:ClosePanel:mxl-core/StashPage2` (reveals page 1). Its X sends
  `PanelManager:ClosePanel:BankExpansionLayout` (closes the stash; the plugin panel closes with it) and Esc closes the plugin
  panel.
* Title string `@d2r:stash`; art is the stock stash frame (custom art last).
* The cube, the gold buttons and the shared tabs stay on the stock panel.

## 5. Packet / sync / multiplayer

The page lives on the player unit server side and D2RLoader/D2RCore replicate and persist it with the character, like any page.
The plugin keeps no state about the page itself (no sidecar of its own), only UI handles, so there is nothing of the port's to
synchronise. TCP/IP with two clients was **not tested** (docs/unported.md row "Shared stash in TCP/IP" is the open row for that).

## 6. Migration and failure modes

* **Existing characters:** nothing to migrate; page 2 starts empty and the stock page is untouched.
* **Plugin missing / `stashpages` off / another plugin owns the page** (the loader allows one custom page per game, e.g. a Charm
  Inventory plugin): `InstallStashPages` reports "off: the loader has a custom page already ..." and the stock strip is hidden
  (`StashPagesOff`, a UI listener hides `MxlPersonalNavigation` when the stock panel is built) so no arrow leads nowhere. A
  character with items on page 6 then refuses to load (D2RCore's protected-page rule), which is the safe direction; the items are
  still in the file. Verified: the save hash is unchanged after a refused load.
* **Page full:** a move is one ItemService transaction (`committed=1` or nothing); `fill` stops when the page takes no more items.
* **Crash/exit with the panel open:** nothing special; the page is saved with the character like page 4.

## 7. Not built: pages 3-10, Mode, Sort (what remains)

Owner decision (2026-10-23): the personal stash stays at 2 pages for now. Not pursued: a D2RLoader feature request for more
custom pages, and the sidecar below.

* **Pages 3-10:** needs "parked" pages: on a page switch, move all items of page 2 into a plugin-owned store and fill page 2 from
  the store for the new page; the store would have to be written next to the `.d2s` atomically and recovered at load. Risk: loss
  on crash between the two steps; vanilla tools would not see parked items. Not done because no safe supported way exists.
* **Mode** (Median's two stash modes): depends on the above.
* **Sort / collect-all-containers (GS7):** `ItemInfo` has no width/height, so a packing sort has no item-size source yet, and
  the order is Median's (not recovered). pSpell 18 (container right click) still works.

## 8. Test evidence

`py -3 tools/game_checks.py --slot 3 all stashpage2 stashpages` (background mode, slot 3, character StashPg): both PASS with
the final DLL. `stashpage2` checks: items created on page 2, listing, the stock strip present, right arrow opens the plugin panel,
left arrow returns, a move 2 -> 1 -> 2 through ItemService, clean-up. By hand (same harness, background clicks): X and Esc on
both panels, switching in every direction, 392 items filled on page 2, save, exit, reload: all 392 present; load without the provider (`stashpages` off + real item on page 6):
refused, save hash unchanged; strip hidden when the part is off. Harness verb `stashpage` (testing.md).
