# D2Sigma's own code: what a player sees or feels, and whether the port has it

Lane `audit-owncode`, 2026-10-23, plugin mxl-core 0.55.0 (main `0bdf9a8`). Research only: nothing here was run, no plugin code changed.

## 1. Why this audit exists

Median XL's engine, D2Sigma.dll, does two things. It patches the 1.13c DLLs at run time (19 patch tables, 2,027 patch sites). That part is
[sigma-patch-audit.md](sigma-patch-audit.md). It also carries its own code: widgets, tables, packets, tooltips, sounds, hotkeys. Median's
documented rules are in [median-rules-audit.md](median-rules-audit.md). Behaviour that D2Sigma implements in its own code and that no
document describes falls between the two. Two such features were found by accident, the buff/debuff icon bar (lane buff-icons) and the
removal of durability (lane no-durability). This audit lists every other functional area of D2Sigma's own code and gives each a port status,
so the same hole does not stay hidden for a third feature.

The two lanes above own their features. Rows that touch them say "lane buff-icons" or "lane no-durability" and are counted as not applicable
here; the work is not redone.

## 2. Method and limits

**Sources.** The Ghidra export of D2Sigma's source tree (`%USERPROFILE%\mxl_extracted\4_sigma_source\engine`: `D2*.cpp`, `ui\*.cpp`,
`mxl_engine\src\**`, `_unattributed\between_X_and_Y.cpp` blocks), the assert and log strings of the DLL (source-file names such as
`BottomPanel:`, `HUD:`, `BossLifebar:`), `docs/sigma-tables.md`, `research/sigma_schema.json`, and the string tables
(`2_txt\strings`; a string id is `table*10000 + index`, 5382 means none). Every table D2Sigma loads counts as a feature (rated in section 10, part B).


**Split.** About 150 own-code files were divided over seven readers by theme: HUD and notifications, items and tooltips, panels and NPCs,
character and skill UI, options and hotkeys and loot filter and automap, gameplay own code, and engine and cross-cutting code. Each row names
the source file and the key addresses, what the player sees, the tables or options it reads, the port status, the evidence, and the player
impact.

**Port evidence** is a file and function in `plugin/src`, a step of `tools/txt_migrate.py`, a check of `tools/game_checks.py`, or a row of
`docs/unported.md`. A status of ported is only given when such evidence exists. A "no hit" means the name was grepped case-insensitive in
`plugin/src`, `tools` and `docs` and not found.

**Status.**

| Status | Meaning |
|---|---|
| ported | the player gets the same thing; evidence cited |
| partly | some of it, or approximated; the gap is named in the row |
| missing | D2Sigma does it, the port does not, and D2R has no equivalent |
| deviation | deliberately different; the `unported.md` row is cited |
| not applicable | D2R does it natively, or it is plumbing, or another lane owns it |
| uncertain | static reading could not decide; the open question is in section 13 |

**Limits.**

1. The Ghidra export is the Sep 21 build, the installed D2Sigma.dll is the Oct 2 build. Addresses above about 0x1007eb00 are off by up to
   0x1d0 (for example TimerText 0x100f4e10 in the export is about 0x100f5040 installed). Names and structure are trusted, exact addresses
   are not.
2. The decompile hides register arguments. Many string ids behind tooltip and HUD lines are known only through the key names in
   `patchstring.txt` (`StrDisplayAlvl` and so on). Where a line's exact wording was inferred the row says so.
3. Packet ids could not be mapped (the Oct DLL's packet tables are zero on disk and filled at run time). Handlers are tied to features, not
   to ids.
4. Median's default `preferences.json` is not in the DLL and was not found on disk, so option defaults are unknown (section 13).
5. No tooltip, panel or sound was looked at in game. Whatever D2R draws natively for a row marked not applicable or partly is taken from
   D2R's layout files, strings and docs, not from a screenshot. Rows where that matters say "verify in game".
6. Rows are per area, not per function. An area with several behaviours is rated by its worst player-visible part, and the row lists the rest.
7. Some features appear in more than one theme (training dummy, Halloween, stash sort, gamble filter, unique limits, NPC greetings, goblin
   notice). Those secondary rows read "dup: see ..." in the status column and are not counted twice. Totals below are of distinct areas.

## 10. Engine, packets, audio, platform, cross-cutting

Scope: engine files D2GameInterface, D2Units, D2Packet, D2PacketClient, D2PacketServer, D2SaveFile, D2Bnetd, D2BnetClient, D2GS, D2Guard, D2Server, D2Games, D2GameClient, D2Clients, D2Multiplayer, D2Window, D2TxtCompile, D2Linkers, `mxl_engine/src/**` and the unattributed gaps around them, plus the cross-cutting search (sound, video, messages, colours, dirs, d2fps, title, version, D2SigmaExt.log, updater, anti-cheat, language, slash commands). Read-only; the repo and the game were not touched.

Method notes. The Ghidra export is the Sep 21 build, the installed DLL is Oct 2; above about 0x1007eb00 addresses differ, so packet ids could not be read from the Oct tables (see Open questions). Addresses below are Sep source addresses unless marked (Oct). Sibling lanes: buff-icons owns `stateicons` / BottomPanel, no-durability owns the durability removal; neither is repeated here.

Reading guide to what these files are: D2GameInterface is Median's own widget framework ("Anvil": themes `classic_sigma` and `tartarus`, text edit, dropdown, slider widgets), D2Units is mostly table-row accessors plus three real functions, the D2Packet* files are the Median handlers patched into the 1.13c packet tables, D2SaveFile is the client-side character and shared-stash stream, D2Bnetd / D2BnetClient / D2GS / D2Server / D2Guard are the realm and server plumbing that D2R replaced.
